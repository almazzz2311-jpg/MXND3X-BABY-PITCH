# MXND3X BABY VOICE

Настоящий VST3-эффект для вокала: независимые **Pitch**, **Formant**, **Mix**, автоматизация, сохранение состояния, шесть пресетов и масштабируемый JUCE-интерфейс с персонажем MXND3X.

## Готовый плагин для Windows

[Скачать Windows x64 VST3](https://github.com/almazzz2311-jpg/MXND3X-BABY-PITCH/actions/runs/40545039800/artifacts/12753041811). Для скачивания артефакта требуется вход в GitHub. Распакуйте ZIP и установите целиком папку `MXND3X BABY VOICE.vst3` по инструкции ниже. Самостоятельная компиляция для установки этого архива не нужна.

## Windows 10/11 x64: сборка

1. Установите **Visual Studio 2022** с компонентами **Desktop development with C++**, MSVC v143 и Windows 10/11 SDK.
2. Установите **CMake 3.24+** и **Git for Windows**, добавив их в PATH.
3. Распакуйте исходники и запустите `build_windows.bat`. Первый запуск требует HTTPS-доступ к GitHub для загрузки зафиксированных версий JUCE и Signalsmith. Зависимости скачиваются в `build-windows/_deps`.
4. Скрипт собирает Release x64, запускает DSP- и интеграционные тесты и копирует весь пакет в **`dist/MXND3X BABY VOICE.vst3`**. При ошибке скрипт завершится ненулевым кодом; старый dist не считается новой сборкой.

Эквивалентные команды:

```bat
cmake -S . -B build-windows -G "Visual Studio 17 2022" -A x64 -DCMAKE_CONFIGURATION_TYPES=Release
cmake --build build-windows --config Release --parallel 2
ctest --test-dir build-windows -C Release --output-on-failure
```

Также добавлен GitHub Actions workflow `.github/workflows/windows.yml`. После загрузки проекта в GitHub он собирает Windows-пакет и предоставляет артефакт `MXND3X-BABY-VOICE-Windows-x64`. Windows-сборка и оба Windows CTest-теста успешно выполнены; фактические результаты и ссылки на Actions находятся в `VALIDATION.md`.

## Установка в FL Studio

1. Закройте FL Studio.
2. Скопируйте **всю папку** `MXND3X BABY VOICE.vst3` из Windows-сборки в `C:\Program Files\Common Files\VST3\`. Windows может запросить права администратора.
3. В FL Studio откройте **Options → Manage plugins → Find installed plugins**.
4. Найдите **MXND3X BABY VOICE**, добавьте в избранное и откройте в слоте эффектов микшера на вокальной дорожке.
5. Начните с пресета **Baby Voice**, уменьшите MIX при необходимости. Включите автоматическую компенсацию задержки микшера.

Используйте 64-битную FL Studio и Windows x64 пакет. Linux `.vst3` содержит ELF-библиотеку и **не загружается в Windows**. При отсутствии runtime установите Microsoft Visual C++ Redistributable 2015–2022 x64.

## Управление

- **PITCH:** −12…+12 st, шаг 0,1. Транспозиция с сохранением длительности и компенсацией исходной формантной огибающей.
- **FORMANT:** −12…+12 st, шаг 0,1. Перенос спектральной огибающей независимо от частот гармоник.
- **MIX:** 0…100%, линейное смешивание; dry задержан точно на сообщаемую хосту задержку движка.
- **BYPASS:** плавный переход к оригиналу с той же задержкой. DSP продолжает работать, чтобы включение не начиналось с пустого буфера. Поддерживается и bypass хоста.
- Перетаскивание мышью; **Shift + drag** для точной настройки; ввод значения в поле под крутилкой. Двойной щелчок: Pitch/Formant → 0, Mix → 100%.
- **RESET:** Natural и bypass off. Все четыре параметра доступны автоматизации и сохраняются в проекте.
- Размер по умолчанию 900×600; изменение размера с сохранением пропорций от 720×480 до 1350×900. Рисование средствами JUCE без OpenGL.

| Preset | Pitch | Formant | Mix |
|---|---:|---:|---:|
| Natural | 0 | 0 | 100% |
| Baby Voice | +7 | +5 | 100% |
| Hyperpop | +12 | +7 | 100% |
| Deep Voice | −7 | −5 | 100% |
| Monster | −12 | −9 | 100% |
| Soft Baby | +4 | +3 | 70% |

## Звуковой движок и ограничения

C++17, JUCE **8.0.12**, Signalsmith Stretch **1.3.2** и Linear **0.6.6**; все Git-версии закреплены в CMake по commit SHA. VST3 SDK входит в JUCE.

Signalsmith использует STFT, согласованное перемещение спектральных пиков и перенос формантной огибающей. `setFormantSemitones(value, true)` компенсирует влияние Pitch на огибающую. Это не эквалайзер и не изменение скорости воспроизведения. Для оценки основного тона используется адаптивный режим библиотеки.

Выбран качественный default preset с распределением вычислений. **Задержка 150 мс**: 6615 / 7200 / 13230 / 14400 сэмплов при 44100 / 48000 / 88200 / 96000 Гц. Хост получает её через `setLatencySamples`. Режим подходит прежде всего для сведения; для живого мониторинга задержка ощутима. Короткие окна уменьшают задержку ценой качества низкого голоса; здесь приоритет отдан качеству.

Pitch и Formant сглаживаются с постоянной времени 30 мс, Mix/Bypass — 20 мс. Выделение буферов происходит в `prepareToPlay`; аудиопоток обрабатывает хостовые блоки порциями до 32 сэмплов без mutex, файлового ввода-вывода и выделений памяти. Mono и stereo обрабатываются одним многоканальным движком с общей спектральной картой.

Спектральная оценка формант приближённая; на шёпоте, согласных, полифонии, резких изменениях и экстремальных ±12 st возможны артефакты. Это не PSOLA и не нейросетевая реконструкция голоса. На предельных настройках высокочастотные компоненты теряются у Найквиста. Исходный уровень не нормализуется; float-сигнал не обрезается искусственно. Спектральная обработка может создавать пики выше исходных: оставляйте запас уровня на вокальном канале. Отсутствие артефактов на любом вокале не гарантируется.

`Assets/brand.png` — подготовленная через инструмент изображения копия присланного визуального референса. Персонаж и надпись в интерфейсе выводятся из отдельных областей этого ресурса без растяжения пропорций. Побайтовая идентичность исходному вложению не заявляется. При необходимости замените `Assets/brand.png` исходным PNG того же размера 1672×941 и пересоберите.

## Linux: разработка и проверка

Debian/Ubuntu prerequisites:

```sh
sudo apt-get install cmake ninja-build g++ git pkg-config libasound2-dev libx11-dev libxext-dev libxinerama-dev libxrandr-dev libxcursor-dev libfreetype-dev libfontconfig-dev libgl-dev
cmake -S . -B build-linux -G Ninja -DCMAKE_BUILD_TYPE=Release
cmake --build build-linux --parallel 2
ctest --test-dir build-linux --output-on-failure
```

В ограниченном Debian-окружении Codex доступен проверяемый rootless-скрипт `bash Scripts/setup_cloud.sh`: он устанавливает инструменты и заголовки в `/workspace/tools`, собирает проект и запускает CTest. Для последующей работы выполните `source /workspace/tools/activate-mxnd3x.sh`. Системные каталоги не изменяются.

Без JUCE/оконных зависимостей можно отдельно собрать тот же DSP:

```sh
cmake -S . -B build-dsp -DCMAKE_BUILD_TYPE=Release -DBABY_BUILD_PLUGIN=OFF
cmake --build build-dsp --parallel 2
ctest --test-dir build-dsp --output-on-failure
```

Для проверки создания, изменения размера, программного рендеринга и уничтожения редактора запустите `PluginTests --gui` в графической сессии либо через `xvfb-run -a`. Исполняемый файл находится в `build-linux/PluginTests_artefacts/Release/`. Команда сохраняет `interface.png` в рабочий каталог. Обычный CTest не требует дисплея. Флаг `--gui-desktop` дополнительно открывает и закрывает нативные окна; используйте его в графической сессии с оконным менеджером (например, Xvfb + Openbox), поскольку один Xvfb не предоставляет необходимые EWMH atoms.

## Проверки и поставка

Фактически выполненные результаты находятся в [VALIDATION.md](VALIDATION.md). `DSPTests` проверяет частоту синуса, перемещение формантной огибающей синтетического голоса, dry/wet, bypass, произвольные блоки, изоляцию каналов, автоматизацию и heap allocations. Он сохраняет WAV до/после для прослушивания. `PluginTests` проверяет пресеты, состояние параметров, форматы каналов и обработку через JUCE AudioProcessor. Флаг `--gui` дополнительно проверяет редактор.

Windows Release x64 собран через Visual Studio 2022; DSPTests и PluginTests прошли на Windows. Загрузка в FL Studio, автоматизация во время playback в реальной DAW и субъективная оценка на музыкальном вокале остаются проверками целевой DAW. Успешная сборка и автоматические тесты не заменяют их.

Для проверки собственной записи и экспорта WAV через процессор доступна команда:

```sh
PluginTests --render input.wav output-baby.wav 1
```

Последний аргумент — номер пресета 0…5 по таблице. Выход сохраняет частоту, число каналов и длительность входа; начальная задержка удаляется, хвост DSP дочитывается. При существующем выходном файле или превышении PCM headroom команда завершается ошибкой, сохраняя исходник.
